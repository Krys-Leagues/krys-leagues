# Production verification relay

This isolated Railway Function receives only signed Vercel `deployment.succeeded`
events for the project IDs in `docs/production-verification/manifest.json`. It
validates Production targeting, project identity, deployment URL, commit SHA, and
repository provenance before dispatching the existing
`vercel-production-deployment` repository event to `Krys-Leagues/krys-leagues`.

Required sealed variables (never commit or return their values):

- `VERCEL_WEBHOOK_SECRET` — the one-time secret generated by Vercel for the webhook.
- `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, and `GITHUB_APP_PRIVATE_KEY_B64` — a
  GitHub App installed on `Krys-Leagues/krys-leagues` only, with Contents: write
  and no other repository or organization permissions. The private key is supplied
  as base64 only to the Railway secret store. For emergency rotation only, the
  implementation also accepts `GITHUB_DISPATCH_TOKEN` as a narrowly scoped
  replacement; it is not required when the App variables are present.

The relay uses an in-memory TTL to coalesce concurrent retries. The downstream
workflow's deterministic `zone_id:deployment_id:commit_sha` concurrency group is
the durable duplicate guard; no database or Production schema is used.

The function intentionally returns only generic error codes and never logs or
returns raw event bodies, signatures, or credentials. `GET /health` is a
non-sensitive liveness check.

Synthetic validation:

```powershell
npx tsx relay/production-verification/index.test.mjs
```

The Vercel webhook should be configured only after the function has its two sealed
variables and its health endpoint has been tested. Select `deployment.succeeded`
for the approved independent projects; do not select Preview events.
